# Contract: Settings and Host Manifests (additions)

Extends [spec 004 contracts/settings.md](../../004-platform-adapters/contracts/settings.md). The definition stays
in `src/adapters/shared/settings.ts`; manifests are generated by `yarn package` and checked by
`yarn verify packages`. Meanings: [data-model.md](../data-model.md).

## New and changed definitions

```ts
type SettingKey = /* 004 keys */ | 'mapsource' | 'mapfolder' | 'maprotation' | 'mapsizemin' | 'mapsizemax' | 'mapunderground'

// Implemented as a file setting with a marker (so validation, WE text inputs and Lively's
// folderDropdown need no new type): a folder, or a .zip standing for one.
interface FileSettingDef extends BaseDef {
  type: 'file'
  fileFilter: '*.lod' | '*.h3m' | '*.zip'   // '*.zip' for mapfolder: Lively's folderDropdown filter
  pick?: 'folder'                           // KDE shows a FolderDialog (+ a .zip dialog and a text field)
}
// BaseDef gained visibleWhen and hint for every type. Wallpaper Engine's default 'game/maps' lives in
// its manifest generator next to the archive defaults.
```

| Key | Def | Order | visibleWhen |
| --- | --- | --- | --- |
| `mapsource` | enum `single` \| `folder`, default `single` | 4 (before `mapfile`) | — |
| `mapfile` | file (unchanged) | 4 | `mapsource = single` |
| `mapfolder` | folder, default null (WE manifest: `game/maps`) | 4 | `mapsource = folder` |
| `maprotation` | int, `input: 'number'`, 0–1440, step 1, default 0, hint `maprotation_hint` | 4 | `mapsource = folder` |
| `mapsizemin` | enum `s m l xl h xh g`, default `s` | 4 | `mapsource = folder` |
| `mapsizemax` | enum `s m l xl h xh g`, default `g` | 4 | `mapsource = folder` |
| `mapunderground` | enum `any two one`, default `any` | 4 | `mapsource = folder` |
| `viewinterval` | max **1440** (was 120) | unchanged | unchanged |

Orders keep the file/map group together; the exact numbers are set in the implementation so every manifest
keeps its current order for existing keys.

`RESERVED_KEYS` is removed: the three keys are now real settings with the meaning reserved for them in spec 004.

Action: `{ key: 'mapnext', type: 'action', label: 'action_mapnext', visibleWhen: { key: 'mapsource', equals: 'folder' } }`,
next to `viewreroll`; handled by the bridges exactly like `viewreroll` (WE checkbox toggle, Lively button, KDE
counter, browser panel button and the `N` key), calling `controller.nextMap()`.

## Validation

- `mapsource`, `mapsizemin`, `mapsizemax`, `mapunderground`: as other enums (unknown → default, reported as
  corrected).
- `mapfolder`: as file values (trimmed text; empty → null). A value ending in `.zip` (case-insensitive) is an
  archive; anything else a folder.
- `maprotation`: as `viewinterval` (typed text, sign, `.`/`,` fraction; rounded, clamped to 0–1440; invalid → 0).
- Settings stored by the previous version (no `mapsource`) validate to `mapsource = single`: nothing changes for
  existing installs (SC-006).

## Wallpaper Engine — `project.json`

- `folder` → `{ type: "textinput", value: "game/maps", text: "ui_mapfolder", condition }` (same reason as the
  archive text inputs: the file dialog accepts images and videos only).
- `mapnext` → a `bool` property; every toggle after the first `applyUserProperties` acts.
- `mapfile` gains `condition: "mapsource.value == \"single\""`.

## Lively

- `folder` → `{ type: "folderDropdown", folder: "userfiles", filter: "*.zip", value: null, text }`.
- Lively has no conditions: every new setting is always shown; labels say "used when the map source is
  "Folder"" (string key `mapfolder_hint`, as `viewx_hint`).
- `mapnext` → `{ type: "button" }`.

## KDE

- `main.xml`: `mapfolder` → `String` (a `file://` URL or a path); the enums → `String`; `maprotation` → `Int`
  0–1440; `mapnext` → `Int` counter.
- `config.qml`: `mapfolder` row = a `FolderDialog` button + an editable text field showing the path (a `.zip`
  path can be typed or chosen with a second "archive" button using `FileDialog` with `*.zip`).
- `packaging/kde/contents/ui/main.qml` `configJson()` lists the new keys; `yarn verify packages` checks that it
  lists every setting and action key (it is hand-written, so this check prevents a key from being forgotten).

## Browser panel

- A "Map source" segmented control; with "Folder": a "Choose a folder of maps" button (`webkitdirectory`), the
  remembered folder's name and map count, the filters, the interval field, "Next map now", and the name of the
  map shown (its title and path).
- Dropping a folder or a `.zip` switches the source to `folder`; dropping a single `.h3m` switches it to
  `single`. Settings persist in `localStorage["h3dynam:settings"]` as today.

## Strings (en, ru)

`setting_mapsource`, `mapsource_single`, `mapsource_folder`, `setting_mapfolder`, `mapfolder_hint`,
`setting_maprotation`, `maprotation_hint`, `setting_mapsizemin`, `setting_mapsizemax`, `mapsize_s` … `mapsize_g`
(with tile counts, e.g. "M (72×72)"), `setting_mapunderground`, `mapunderground_any|two|one`, `action_mapnext`,
`panel_choose_folder`, `panel_folder_summary`, `panel_current_map`, `msg_FOLDER_EMPTY`, `msg_FOLDER_FILTERED`,
`msg_FOLDER_UNREADABLE`. `viewinterval` label unchanged; its max changes only.
